# Flutter Project Structure — Clean Architecture

> Standard folder structure for Flutter projects following Clean Architecture principles. Scales from small apps to large team projects.

---

## Top-Level Structure

```
my_flutter_app/
├── .github/
│   ├── workflows/
│   │   ├── ci.yml                  # CI pipeline (analyze, test, build)
│   │   └── deploy.yml              # CD pipeline (deploy to stores)
│   └── copilot-instructions.md    # GitHub Copilot context
├── android/                       # Android native project
├── ios/                           # iOS native project
├── lib/                           # Dart source code (main)
├── test/                          # Unit and widget tests
├── integration_test/              # Integration / E2E tests
├── assets/                        # Images, fonts, Lottie/Rive files
├── l10n/                          # Localization ARB files
├── fastlane/                      # Fastlane deployment lanes
├── analysis_options.yaml          # Lint rules
├── pubspec.yaml                   # Dependencies
└── README.md
```

## Layer Responsibilities

### Presentation Layer (`features/*/presentation/`)

**What lives here:**
- Flutter widgets and pages
- BLoC / Cubit / ViewModel / Notifier (Riverpod)
- Route builders
- UI-specific state classes

**Rules:**
- ✅ May import from `domain/` (use cases, entities)
- ✅ May import from `core/widgets/` and `core/theme/`
- ❌ Must NOT import from `data/` directly
- ❌ Must NOT contain business logic
- ❌ Must NOT call Dio or databases directly

---

### Domain Layer (`features/*/domain/`)

**What lives here:**
- Entity classes (pure Dart, `@freezed`)
- Repository interfaces (`abstract interface class`)
- Use case classes (one per operation)
- Domain-specific value objects and enums

**Rules:**
- ✅ May import `dart:core`, `dart:async`, `fpdart` (for Either/Option)
- ❌ Must NOT import `package:flutter/...`
- ❌ Must NOT import from `data/` or `presentation/`
- ❌ Must NOT contain network or database code
- ❌ Must NOT depend on `GetIt` or other DI containers

---

### Data Layer (`features/*/data/`)

**What lives here:**
- Repository implementations (implements domain interface)
- Data Transfer Objects (DTOs) with `fromJson`/`toJson`
- Remote data sources (Dio API calls)
- Local data sources (Hive/SQLite access)
- Mappers (`dto.toDomain()`)

**Rules:**
- ✅ May import from `domain/` (implements repository interfaces, maps to entities)
- ✅ May import `Dio`, `Hive`, `sqflite`, `drift`
- ✅ May import from `core/network/` and `core/storage/`
- ❌ Must NOT import from `presentation/`
- ❌ Must NOT import Flutter UI widgets

## Naming Conventions

### Files

| Type | Convention | Example |
|---|---|---|
| Entity | `{entity}.dart` | `user.dart` |
| DTO | `{entity}_dto.dart` | `user_dto.dart` |
| Repository interface | `{entity}_repository.dart` | `user_repository.dart` |
| Repository impl | `{entity}_repository_impl.dart` | `user_repository_impl.dart` |
| Use case | `{verb}_{entity}_use_case.dart` | `get_user_use_case.dart` |
| BLoC | `{feature}_bloc.dart` | `auth_bloc.dart` |
| BLoC Event | `{feature}_event.dart` | `auth_event.dart` |
| BLoC State | `{feature}_state.dart` | `auth_state.dart` |
| Cubit | `{feature}_cubit.dart` | `theme_cubit.dart` |
| Page | `{feature}_page.dart` | `login_page.dart` |
| Widget | `{descriptive_name}.dart` | `product_card.dart` |
| Test | `{source_file}_test.dart` | `user_repository_impl_test.dart` |

### Classes

| Type | Convention | Example |
|---|---|---|
| Entity | `UpperCamelCase` | `class User` |
| DTO | `UpperCamelCase + Dto` | `class UserDto` |
| Repository interface | `UpperCamelCase + Repository` | `abstract class UserRepository` |
| Repository impl | `UpperCamelCase + RepositoryImpl` | `class UserRepositoryImpl` |
| Use case | `Verb + Entity + UseCase` | `class GetUserUseCase` |
| BLoC | `Feature + Bloc` | `class AuthBloc` |
| Event | `PastTense (event happened)` | `class LoginRequested` |
| State | `Feature + Phase` | `class AuthLoading`, `class AuthSuccess` |
| Failure | `Noun + Failure` | `class NetworkFailure`, `class ServerFailure` |

## Import / Dependency Direction

```
        ┌─────────────────────────────────────────────┐
        │              PRESENTATION                    │
        │  (Widgets, Pages, BLoC, ViewModel)          │
        └─────────────────┬───────────────────────────┘
                          │ depends on
                          ▼
        ┌─────────────────────────────────────────────┐
        │                DOMAIN                       │
        │  (Entities, Use Cases, Repository Interfaces│
        └─────────────────┬───────────────────────────┘
                          ▲ implements
                          │
        ┌─────────────────────────────────────────────┐
        │                 DATA                        │
        │  (Repository Impls, DTOs, API, Local DB)    │
        └─────────────────────────────────────────────┘
```

**Rule: Arrows only point inward toward Domain. No reverse dependencies.**

```
✅ Presentation → Domain
✅ Data → Domain (implements)
❌ Domain → Presentation
❌ Domain → Data
❌ Presentation → Data (direct)
```

## Barrel Exports

Each feature exports a single barrel file for clean imports:

```dart
// features/auth/auth.dart
export 'domain/entities/user.dart';
export 'domain/use_cases/login_use_case.dart';
export 'presentation/bloc/auth_bloc.dart';
export 'presentation/bloc/auth_event.dart';
export 'presentation/bloc/auth_state.dart';
export 'presentation/pages/login_page.dart';

// Usage from another feature (only domain-safe exports)
import 'package:my_app/features/auth/auth.dart';
```
